# MachineryPartsHub — технологический стек и деплой

Рекомендации по стеку для сайта автозапчастей и сервиса: каталог, форма запроса, панель менеджера и бесплатный деплой.

## Исходный стек

- **Backend:** Django, Django REST Framework
- **База данных:** PostgreSQL (Redis, если нужна скорость)
- **Аутентификация:** djangorestframework-simplejwt
- **Тесты:** pytest
- **Frontend:** React (TypeScript + Vite)
- **Деплой:** Cloudflare или Render

В целом стек подходит для каталога запчастей с заявками. Ниже — уточнения и дополнения.

## Что стоит уточнить

**JWT нужен не всем.** Покупателям аккаунты не нужны: каталог и форма запроса открыты без входа. `simplejwt` пригодится, только если делать собственную панель менеджера на React. Иначе менеджер может работать в **Django Admin**: она встроена, использует сессионную авторизацию и сразу даёт редактирование каталога и просмотр заявок.

**Redis не обязателен на старте.** Он нужен для кэша каталога, ограничения частоты запросов к форме и очередей фоновых задач. Подключайте его, когда это понадобится.

## Что добавить

### Backend

- `django-filter` — фильтры по категории, марке и модели.
- `drf-spectacular` — документация API (Swagger).
- `django-cors-headers` — связь с фронтендом.
- `gunicorn` и `whitenoise` — запуск и статика; `django-environ` — настройки и секреты.
- `django-storages` — загрузка фото. На бесплатных хостингах диск временный, поэтому фото нужно хранить в объектном хранилище (Cloudflare R2 или S3).
- Поиск: сначала PostgreSQL (`pg_trgm` и full-text), Meilisearch — если позиций станет много.
- `openpyxl` или `pandas` — импорт прайс-листов из Excel.
- Уведомления о заявках в Telegram: обычный запрос к Bot API. Celery — позже, при росте нагрузки.

### Frontend (React + TypeScript + Vite)

- Tailwind CSS, React Router.
- TanStack Query — запросы и кэш.
- React Hook Form + Zod — форма и валидация.

### Тесты и качество

- Backend: `pytest-django`, `factory_boy`.
- Frontend: Vitest.
- Сквозные тесты: Playwright, главный сценарий «найти запчасть → отправить запрос».
- `ruff` и `pre-commit` — стиль кода; GitHub Actions — автозапуск тестов; Docker — одинаковое окружение.

### Безопасность

- Cloudflare Turnstile (бесплатная капча) и DRF throttling против спама в форме.
- Sentry — отслеживание ошибок.
- Политика конфиденциальности и согласие на обработку персональных данных, так как форма собирает имя и телефон.

## Деплой

Cloudflare и Render лучше не выбирать между собой, а разделить:

| Часть | Где разместить |
| --- | --- |
| Frontend | Cloudflare Pages (бесплатно, CDN) |
| Backend (Django) | Render (Cloudflare не подходит для обычного Django) |
| База данных | PostgreSQL на Render или внешний сервис |
| Фото | Cloudflare R2 |

### Ограничения бесплатного Render

- Бесплатный веб-сервис засыпает после 15 минут без запросов и просыпается около минуты.
- Бесплатная база Postgres на Render удаляется через 30 дней. Другие источники упоминают льготный период, поэтому условия нужно проверить на сайте Render.
- Для демонстрации руководству это терпимо: откройте сайт заранее.
- Для рабочего сайта бесплатный вариант не подходит. Постоянно работающее приложение с базой на Render обойдётся примерно в 13 долларов в месяц.
- Бесплатные альтернативы с постоянным хранением базы (Neon, Supabase) существуют, но их лимиты нужно проверить перед выбором.

## Итоговая схема

React (TypeScript, Vite) на Cloudflare Pages → Django REST API на Render → PostgreSQL. Фото хранятся в Cloudflare R2, Redis подключается позже, менеджер работает в Django Admin, заявки приходят в Telegram.
